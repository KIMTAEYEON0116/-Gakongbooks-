# 📚 가공독서회 (Gakong Reading Club)

> **세상에 없는 책을 AI가 만들고, 독자들이 그 책을 읽은 척 감상을 나누는 가상 독서 모임입니다.**

읽지 않은 책에 대해 이야기한다는 설정 위에 세워진 서비스입니다. Google Gemini 2.5 Flash가 제목·작가·줄거리·추천사·토론 질문까지 갖춘 허구의 책을 만들면, 그 책으로 **10일짜리 독서방**이 열립니다. 독자들은 줄거리만 읽고 상상으로 감상을 남기고, `@사회자`를 부르면 AI가 토론을 이어받습니다. 10일이 지나면 방은 닫히고 대화 전체가 **아카이브**에 기록으로 남습니다.

**한국어 · 일본어** 두 언어를 지원하며, 데스크톱과 모바일 모두 대응합니다.

```
AI가 책을 만든다 → 독서방이 열린다(10일) → 상상으로 감상을 나눈다 → 아카이브에 남는다
```

## 🚀 빠른 시작

### 1. 설정 파일 준비

`.env.example`을 복사해 `.env`를 만들고 값을 채웁니다. 모든 환경변수는 `config.py` 한 곳에서만 읽습니다.

```bash
cp .env.example .env
```

**최소한 이 네 가지는 채워야 합니다.**

| 항목 | 설명 |
|---|---|
| `DATABASE_URL` | `mysql+pymysql://사용자:비밀번호@호스트:포트/DB이름` |
| `GEMINI_API_KEY` | [Google AI Studio](https://aistudio.google.com/)에서 발급 |
| `JWT_SECRET_KEY` | `python -c "import secrets; print(secrets.token_urlsafe(48))"` 로 생성 |
| `OWNER_ADMIN_EMAIL` | 관리자 권한을 가질 계정의 이메일 (한 명만) |

### 2. 의존성 설치

```bash
pip install -r requirements.txt
```

### 3. 실행

```bash
uvicorn main:app --reload --port 8001
```

브라우저에서 `http://localhost:8001`로 접속합니다.

> [!TIP]
> 포트가 이미 쓰이고 있으면 `--port` 값만 바꾸면 됩니다. 개발 환경(`APP_ENV=development`)에서는 localhost의 모든 포트가 CORS 허용 대상이라 추가 설정이 필요 없습니다.
> 다만 비밀번호 재설정 메일 링크를 테스트하려면 `.env`의 `APP_BASE_URL`도 같은 포트로 맞춰주세요.

> [!IMPORTANT]
> 운영 배포 시에는 `APP_ENV=production`으로 설정하세요. 이 값이 `production`일 때만 필수 시크릿 검증(누락 시 기동 중단), `/docs` 비노출, HSTS 헤더가 활성화됩니다.

**서버 없이 화면만 보기** — 프로젝트 루트의 `index_standalone.html`을 더블클릭하면 UI와 화면 전환을 오프라인으로 확인할 수 있습니다. AI 생성·DB 저장·채팅은 동작하지 않습니다.

## ✨ 핵심 기능

### 📖 AI 도서 생성과 수명 관리

장르·분위기·핵심 소재를 고르면 Gemini가 제목, 작가, 시놉시스, 한 줄 서평, 토론 질문까지 갖춘 도서 한 세트를 만들어 냅니다.

- **후보 보관함(Pool)** — 한 번에 3권을 제안하고, 선택받지 못한 2권은 버리지 않고 DB에 보관합니다. 다음 생성 때 오래된 것부터 선입선출로 꺼내 쓰므로 남는 책이 없고, 보관함에 3권 이상 쌓이면 AI 호출 자체를 생략해 **API 비용과 응답 속도를 아낍니다.**
- **10일 수명** — 생성된 책은 10일간 활성 독서방으로 노출됩니다. 마감은 **날짜 기준**이라 종료일 당일 23시 59분까지 열려 있고 자정에 닫힙니다. 모든 방이 같은 시각에 닫히므로 언제 끝나는지 예측할 수 있습니다.
- **닫는 인사** — 방이 닫히기 직전 AI 사회자가 그 방의 대화를 읽고 **폐회 인사**를 채팅에 남깁니다. 통계와 베스트 감상은 아카이브 화면이 따로 보여주므로, 이 글에는 숫자나 인용 없이 이야기가 어디로 흘렀는지만 담깁니다. 이 메시지까지 함께 이관되어 아카이브의 대화 기록도 닫는 말로 끝납니다.
- **자동 보충** — 활성 독서방이 0권이 되면 홈이 비어버리므로, 1시간마다 확인해 0권일 때만 보관함 우선으로 3권을 채웁니다. 1권이라도 있으면 개입하지 않습니다.
- **관리자 삭제** — 관리자로 로그인하면 도서 상세에 삭제 버튼이 나타나, 부적절한 도서를 채팅·평점·표지 파일까지 연쇄(Cascade)로 정리합니다.

### 🎙️ AI 사회자 (Gemini 2.5 Flash)

독자들의 자율적인 대화를 우선하고, **불려야 나섭니다.**

- 예전의 "댓글 4개마다 자동 개입" 방식을 없앴습니다. `@사회자` 또는 `@moderator`로 명시적으로 부를 때만 응답합니다.
- 응답은 **공감 1문장 + 세계관 상상 1문장 + 역질문 1문장**의 3단 구성을 따릅니다.
- 사회자는 서비스 전체에 **한 계정만** 존재하며, 로그인이 차단된 봇 계정입니다(운영 권한 없음).
- Gemini 2.5 Flash는 추론 토큰을 먼저 소모하므로 `maxOutputTokens`를 **4096**으로 두고, 채팅 `content` 컬럼을 `TEXT`로 두어 **문장이 잘리지 않게** 했습니다.

### ❤️ 반응과 답장

- 반응은 **4종으로 고정**됩니다 — `❤️` 공감해요 · `🤔` 생각이 달라요 · `😄` 재밌어요 · `✨` 인상 깊어요.
- 반응 집계는 서버가 계산해 내려주므로 채팅방을 열지 않아도 도서 상세에서 바로 보입니다.
- **채팅 본문에는 이모지를 쓰지 않습니다.** 감정 표현은 반응이 담당한다는 원칙이며, AI 사회자 응답에도 동일하게 적용됩니다.

### 🗂 아카이브

종료된 독서방은 대화 전체와 함께 아카이브에 남습니다.

- 종료월 기준으로 묶은 **월별 서가** 형태로, 서가 기둥·월 라벨·연도 마커·스크롤 고정 헤더를 둔 에디토리얼 레이아웃입니다.
- 권수가 늘어날 때를 대비해 **연도 칩 필터 · 최신 3개월만 펼침 · 12개월씩 더 보기**를 적용했습니다. 120권·48개월 합성 데이터에서 초기 렌더 1ms에 카드 8장만 생성됩니다.

### 👑 명예의 전당

도서 상세 하단에서 그 방의 **베스트 상상 리뷰**를 순위와 공감 수와 함께 보여줍니다.

### 🌏 다국어 · 반응형

- **한국어 / 일본어** — 화면 문자열은 사전 한 곳(`I18N_DICT`, 301쌍)만 바라보며 두 언어 모두 누락이 없습니다. 새로고침해도 선택한 언어가 유지됩니다.
- **도서 데이터 번역** — 제목·작가·줄거리·추천사·토론 질문과 사회자 메시지를 일본어로 번역해 저장합니다(도서는 `books.i18n_ja`에 JSON으로, 사회자 메시지는 `content_ja`에). 번역은 저장 전에 **키 누락·한글 잔존·구분 기호 보존**을 검사하고, 하나라도 걸리면 저장하지 않고 다음 기회에 다시 시도합니다. 일본어 화면에 한국어가 섞이지 않게 하려는 것입니다. 번역이 아직 없으면 원문을 쓰므로 화면이 비지는 않습니다.
- **글꼴** — **Noto Sans 한 벌**로 통일했습니다(무료, SIL OFL). 참여 인원·평점·D-day 같은 작은 숫자 라벨이 화면 곳곳에 있어 그 크기에서 획이 또렷한 고딕을 택했습니다. `html[lang]`에 따라 한국어는 KR, 일본어는 JP 자형이 우선됩니다. 예전에는 명조·고딕에 더해 Inter·Playfair·Outfit까지 다섯 벌을 불러왔는데, 뒤의 셋은 실제로 쓰이는 곳이 한 군데도 없어 함께 정리했습니다. 후보 비교는 [`static/mockups/font-compare.html`](static/mockups/font-compare.html)에 남겼습니다.
- **모바일** — 태블릿(900px) · 모바일(640px) · 소형(340px) 3단계 브레이크포인트를 `mobile.css` 한 파일에서 관리합니다. 데스크톱 스타일은 건드리지 않고 덮어쓰기만 합니다.
- **읽기 환경** — 8~10px로 쓰이던 마이크로 폰트 40여 곳을 12~13px로 올리고, 줄거리 본문과 독서방 댓글을 15.5px·줄간격 1.85로 두었습니다.

## 🛠 기술 스택

### Backend

| 구분 | 사용 기술 |
|---|---|
| 프레임워크 | FastAPI (Python 3.10+) |
| ORM / DB | SQLAlchemy · MySQL (SQLite 호환) |
| AI | Google Gemini 2.5 Flash (`httpx` 비동기) |
| 서버 | Uvicorn |
| 인증 | JWT(PyJWT) + bcrypt, 1회용 비밀번호 재설정 토큰(해시 저장) |
| 보안 | 슬라이딩 윈도우 레이트리밋, CSP 등 보안 응답 헤더 미들웨어 |

### Frontend

| 구분 | 사용 기술 |
|---|---|
| 템플릿 | Jinja2 모듈화 (`templates/`) |
| 스크립트 | Vanilla JS (`static/js/books.js`) — 빌드 도구 없음 |
| 디자인 | 다크 테마, 글래스모피즘, 명예의 전당 골드 테마 |
| 반응형 | `mobile.css` 단일 레이어 · 3단계 브레이크포인트 |
| 통신 | 온디맨드 REST 호출 (첫 진입 시 전체 로딩 없음) |

## 🔐 보안 설계

인증·인가 로직은 세 모듈(`config.py` · `security.py` · `auth.py`)에 모여 있습니다. **새 기능을 추가할 때 아래 규칙만 지키면 됩니다.**

| 하고 싶은 일 | 사용할 것 |
|---|---|
| 새 환경변수·시크릿 추가 | `config.py`에 한 줄 추가 (필수값이면 `require_secret()`) |
| 로그인 필수 엔드포인트 | `Depends(auth.get_current_user_id)` 또는 `Depends(auth.get_current_user)` |
| 관리자 전용 엔드포인트 | `Depends(auth.require_admin)` — 엔드포인트 안에서 `is_admin`을 직접 검사하지 않습니다 |
| 호출 횟수 제한 | `security.RateLimiter` 인스턴스를 만들고 `check()`/`record()`/`hit()` 호출 |
| 비밀번호 변경 | `auth.set_password()` — 해시 교체와 기존 토큰 무효화가 함께 처리됩니다 |
| 사용자 문자열을 화면에 출력 | `textContent`, 또는 `innerHTML`이 꼭 필요하면 `escHtml()`을 반드시 통과 |
| DB 컬럼 추가 | `main.py`의 `_SCHEMA_PATCHES` 목록에 한 줄 추가 |

**적용된 보호 장치**

- 비밀번호 재설정은 **1회용 링크 방식**(SHA-256 해시만 DB 저장, 30분 만료). 가입 여부와 무관하게 같은 응답을 반환해 이메일 열거를 차단합니다.
- 비밀번호 변경·재설정 시 `users.password_changed_at`과 토큰의 `iat`를 비교해 **기존 JWT를 모두 무효화**합니다.
- 로그인 레이트리밋은 **IP와 계정 두 축**으로 분리해, 남의 이메일로 실패를 쌓아 피해자를 잠그는 방식을 막습니다.
- CSP · `X-Frame-Options` · nosniff · Referrer-Policy를 모든 응답에 부착하며, 운영에서는 HSTS가 추가되고 `/docs`가 비활성화됩니다.
- 관리자는 `OWNER_ADMIN_EMAIL` 한 명, AI 사회자는 봇 계정 하나로 기동 시마다 정리됩니다(`enforce_roles()`). 봇은 로그인이 차단되고, 프론트는 서버가 내려주는 `isBot` 플래그로 사회자를 판별해 **공식 계정 사칭이 불가능합니다.**

## 🚢 배포 체크리스트

이 서비스는 **단일 프로세스**를 전제로 만들어졌습니다. 레이트리밋 카운터가 프로세스 메모리에 있고, 만료 아카이브·자동 보충 루프가 프로세스 안에서 돌기 때문입니다. `--workers 2` 이상으로 띄우면 제한이 워커별로 쪼개지고 자동 보충이 워커 수만큼 Gemini를 중복 호출합니다. **워커는 1개로 두고, 앞에 리버스 프록시를 세우세요.**

| 순서 | 할 일 | 왜 |
|---|---|---|
| 1 | `APP_ENV=production` | 필수 시크릿 검증, `/docs` 비노출, HSTS가 이 값에서만 켜집니다 |
| 2 | `JWT_SECRET_KEY`, `OWNER_ADMIN_EMAIL`, `SMTP_USERNAME`, `SMTP_PASSWORD` 설정 | 하나라도 비어 있으면 **기동이 거부**됩니다. SMTP가 없으면 비밀번호 찾기가 성공 메시지만 띄우고 실제로는 아무것도 보내지 않아, 사용자가 계정을 영구히 잃습니다 |
| 3 | `APP_BASE_URL`을 실제 접속 주소로 | 비밀번호 재설정 메일의 링크가 이 값으로 만들어집니다 |
| 4 | `TRUSTED_PROXY_IPS`에 프록시 IP 지정 | `X-Forwarded-For`는 위조가 자유로운 헤더입니다. 여기 적힌 IP에서 온 요청만 그 헤더를 믿습니다. 비워 두면 헤더를 무시하므로 프록시 뒤에서는 모든 요청이 프록시 IP로 보여 **레이트리밋이 전체 사용자에게 한 덩어리로** 걸립니다 |
| 5 | `ALLOW_ORIGINS`에 서비스 도메인 | 운영에서는 localhost 자동 허용이 꺼집니다 |
| 6 | 워커 1개로 기동 | 위 단일 프로세스 전제 |

```bash
uvicorn main:app --host 127.0.0.1 --port 8001 --workers 1
```

프록시(Nginx 예시)는 원 클라이언트 IP를 넘겨주기만 하면 됩니다.

```nginx
location / {
    proxy_pass         http://127.0.0.1:8001;
    proxy_set_header   Host              $host;
    proxy_set_header   X-Forwarded-For   $remote_addr;
    proxy_set_header   X-Forwarded-Proto $scheme;
}
```

이 구성이면 `.env`의 `TRUSTED_PROXY_IPS=127.0.0.1`입니다.

**콘텐츠에 대해** — 독서방과 아카이브에는 서비스 소개용으로 미리 작성한 가상 독자의 대화가 들어 있습니다. 해당 메시지에는 닉네임 옆에 **「예시」** 표시가 붙고 방 상단에 안내 문구가 나오므로, 실사용자가 실제 사람의 감상으로 오해하지 않습니다. 가상 독자 계정은 `@gakong.com` 도메인을 쓰며 이 도메인으로는 가입이 거부됩니다.

**아직 없는 것** — 테스트, CI, Dockerfile, DB 마이그레이션 도구(Alembic), `logging` 기반 로그. 포트폴리오 데모 공개에는 지장이 없지만, 불특정 사용자를 받기 전에는 최소한 주요 API 스모크 테스트와 로그 설정을 먼저 갖추는 것을 권합니다.
