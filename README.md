## 🆕 최근 업데이트 (2026년 8월) — 보안 재구성 · 모바일 UI · 일본어 완성 · 아카이브 월별 서가 · 역할 분리 · 채팅 정책 정비

전체 코드베이스 보안 점검 후, 발견된 취약점을 개별 패치가 아닌 **구조 개선 방식**으로 수정했습니다. 설정은 `config.py`, 요청 단위 보안 장치는 `security.py`, 인증·인가는 `auth.py`로 일원화하여 같은 유형의 누락이 반복되지 않도록 했습니다.

- **비밀번호 재설정을 토큰 링크 방식으로 전면 교체 (심각)**: 기존에는 `/api/auth/find-password`가 **이메일 주소만 알면 남의 비밀번호를 즉시 임시값으로 바꿔버려**, 누구나 타인의 계정을 영구 잠금 상태로 만들 수 있었습니다. 이제 요청만으로는 비밀번호가 바뀌지 않고, 메일로 받은 **1회용 재설정 링크**(SHA-256 해시만 DB 저장, 30분 만료)를 눌러야 변경됩니다. 가입 여부와 무관하게 동일한 응답을 반환해 **가입자 이메일 열거**도 차단했습니다. (신규: `POST /api/auth/reset-password`, `GET /reset-password`)
- **시크릿 하드코딩 폴백 제거 (심각)**: `JWT_SECRET_KEY`가 없을 때 소스코드에 박힌 고정 문자열로 기동하던 동작을 없앴습니다. `APP_ENV=production`에서는 필수 시크릿이 비어 있으면 **서버가 기동되지 않고**, 개발 환경에서는 매 기동 새 난수를 만들어 씁니다(고정값이 아니므로 저장소를 본 사람이 토큰을 위조할 수 없습니다). `APP_ENV`에 오타가 나면 조용히 개발 모드로 떨어지지 않도록 값 자체를 검증합니다.
- **저장형 XSS 잔존 지점 전수 차단**: 도서 제목·줄거리·저자, 랭킹 닉네임, AI 한줄평, 후보 카드, 책등 등 **25개 삽입 지점**에 이스케이프를 적용하고, `escHtml()`이 따옴표까지 처리하도록 강화했습니다. 표지 CSS를 만드는 `getCoverCss()` 내부에 URL·색상 정제를 넣어 호출부 10곳을 한 번에 보호하고, 채팅 검색 하이라이트는 HTML 문자열 치환에서 **텍스트 노드 순회 방식**으로 교체했습니다.
- **토큰 무효화 수단 도입**: 비밀번호를 바꿔도 기존 JWT가 24시간 유효하던 문제를 해결했습니다. `users.password_changed_at`과 토큰의 `iat`를 비교해, 비밀번호 변경·재설정 시 **기존 토큰이 모두 무효화**되고 탈퇴한 계정의 토큰도 즉시 거부됩니다.
- **레이트리밋 정책 정비**: 임시 dict를 슬라이딩 윈도우 제한기(`security.RateLimiter`)로 교체하고, 로그인을 **IP + 계정 두 축**으로 분리해 "남의 이메일로 실패를 쌓아 피해자를 잠그는" DoS를 어렵게 했습니다. 회원가입·비밀번호 재설정에도 제한을 추가했습니다.
- **인가 검사 일원화 및 무인증 API 차단**: 엔드포인트마다 복사돼 있던 관리자 검사를 `auth.require_admin` 의존성으로 통일하고, 인증 없이 호출 가능했던 `POST /api/books/auto-archive`를 관리자 전용으로 막았습니다.
- **보안 헤더·CORS·문서 노출 정비**: CSP·`X-Frame-Options`·nosniff·Referrer-Policy를 모든 응답에 부착(운영은 HSTS 추가), CORS 와일드카드(`*`)를 금지, 운영에서 `/docs` 비활성화. 개발 환경에서는 포트를 바꿔 띄워도 되도록 localhost의 모든 포트를 자동 허용합니다.
- **민감정보 로그 노출 제거**: 임시 비밀번호 평문 출력과 SMTP 예외 메시지 노출을 제거했습니다.
- **모바일(휴대폰) UI 대응**: 기존 CSS에는 미디어쿼리가 하나도 없어 휴대폰에서 책 카드가 78px로 찌그러지고 내비게이션이 3줄로 넘치는 등 사실상 사용이 어려웠습니다. 모바일 전용 레이어 `static/css/mobile.css`를 새로 두어 **카드 2열, 내비게이션 한 줄 가로 스와이프, 여백 축소, 도서 상세·평점 통계 1단 배치, 채팅 헤더 말줄임 + 탭하면 펼쳐지는 검색창**으로 정리했습니다. 데스크톱 스타일(`styles.css`)은 건드리지 않고 덮어쓰기만 하므로 기존 화면은 그대로입니다. 휴대폰 폭(375·393·430px)에서 홈·상세·후보·서재·안내·약관·개인정보·문의·로그인·회원가입·아카이브 11개 화면 모두 가로 스크롤 없이 표시되는 것을 확인했습니다. 내비게이션은 430px 화면에 메뉴가 모두 들어오고, 더 좁은 화면에서는 메뉴만 옆으로 스크롤되며 **로그인 버튼은 오른쪽에 고정되어 항상 보입니다.**
- **일본어 UI 전수 완성**: 로그인·회원가입·내 서재 게이트, 도서 상세 라벨, 토스트·확인창, 입력창 안내문(placeholder)과 툴팁까지 남아 있던 한국어를 모두 번역했습니다. 문구 조회 헬퍼 `t(key)`를 도입해 화면 문자열이 사전 한 곳(`I18N_DICT`, 한/일 262쌍)만 바라보게 정리했고, 새로고침해도 선택한 언어가 유지됩니다. 이제 남은 한국어는 **DB에 저장된 책 데이터(제목·줄거리 등)뿐**입니다.
- **일본어 글꼴 적용**: 지정만 되어 있고 로드되지 않던 본문 폰트를 바로잡아 **Noto Sans/Serif KR·JP**(무료, SIL OFL)를 불러오고, `html[lang]`에 따라 언어에 맞는 자형이 우선되도록 분리했습니다. 일본어 가나·한자가 네모로 깨지지 않습니다.
- **아카이브 월별 서가**: 종료된 독서방을 종료월 기준으로 묶어 보여줍니다. 왼쪽 서가 기둥과 달마다의 점·세리프 월 라벨, 연도 마커, 스크롤 시 고정되는 월 헤더로 사이트의 에디토리얼 톤을 따랐습니다. 권수가 많아질 때를 대비해 **연도 칩 필터 · 최신 3개월만 펼침 · 12개월씩 더 보기**를 넣어, 120권·48개월 합성 데이터에서도 초기 렌더 1ms에 카드 8장만 생성됩니다.
- **관리자 / AI 사회자 역할 분리**: 하나의 `is_admin` 플래그가 "운영 권한"과 "AI 사회자 봇"을 겸하고 있어, **봇 계정이 도서 삭제 권한까지 갖고** 있었습니다. `is_bot` 컬럼을 신설해 두 개념을 분리하고, 기동 시마다 역할을 정리하는 `enforce_roles()`를 추가했습니다 — 운영자는 `.env`의 `OWNER_ADMIN_EMAIL` 한 명, AI 사회자는 봇 계정 하나로 고정됩니다. 봇 계정은 로그인이 차단되며(403), 프론트도 닉네임 추측 대신 서버가 내려주는 `isBot` 플래그로 사회자를 판별해 **공식 계정 사칭**이 불가능해졌습니다.

## ✨ 핵심 기능 소개

### 1. 실시간 AI 도서 생성 및 수명 관리
- **Google Gemini API 연동**: 사용자가 장르, 분위기, 핵심 소재를 선택하면 Gemini가 실시간으로 독창적인 도서 메타 데이터(제목, 작가, 시놉시스, 한 줄 서평, 토론 질문 등)를 생성합니다.
- **후보 도서 보관함(Pool) FIFO 순차 소진**: 3권 중 선택받지 못한 2권은 DB 보관함(`pool`)에 자동 저장되며, "다음 책 생성" 시 오래 보관된 도서부터 선입선출(FIFO)로 불러와 **남는 책 없이 100% 깔끔하게 소진**합니다. (보관함에 3권 이상 축적 시 AI 생성을 생략하고 보관 도서를 즉시 반환하여 API 응답 속도 및 비용 최적화)
- **도서 자동 수명 관리**: 생성된 가상 도서는 **10일 동안 일반 도서로 노출**되며, 기한 만료 후 자동으로 **아카이브 열람** 상태로 전환됩니다.
- **관리자 권한 연동**: 관리자 계정 로그인 시 도서 상세 페이지에서 삭제 버튼이 노출되어 부적절한 도서를 연쇄(Cascade) 정단 삭제할 수 있습니다.

### 2. 🎙️ 독자 대화 우선 모드 AI 사회자 (Gemini 2.5 Flash)
- **독자 자율 대화 존중**: 4개 댓글마다 자동 개입하던 방식을 완전 차단하여 독자들 간의 자율적인 상상과 대화를 최우선 보장합니다.
- **명시적 `@사회자` 멘션 1회 응답**: 독자가 필요에 따라 `@사회자` 또는 `@moderator`를 태그했을 때만 3단계 샌드위치 공식(공감 1문장 + 비하인드 상상 1문장 + 역질문 1문장)으로 정갈하고 풍성하게 응답합니다.
- **문장 잘림 없는 완성형 텍스트**: Gemini 2.5 Flash 추론(Thinking Token ~950개) 모델 특성에 맞춰 `maxOutputTokens`를 **4096**으로 대폭 확장하고, DB `content` 컬럼을 `TEXT` 타입으로 마이그레이션하여 잘림 없는 문장을 제공합니다.

## 🛠 기술 스택 (Tech Stack)

### Backend
- **Core Framework**: FastAPI (Python 3.10+)
- **Database ORM**: SQLAlchemy / SQLite & MySQL 지원
- **AI Core**: Google Gemini 2.5 Flash API (`httpx` 비동기 통신)
- **Server**: Uvicorn
- **인증/보안**: JWT(PyJWT) + bcrypt 해싱, 비밀번호 재설정 토큰(1회용/해시 저장), 슬라이딩 윈도우 레이트리밋, CSP 등 보안 응답 헤더 미들웨어

### Frontend
- **HTML/CSS/JS**: Jinja2 모듈화 템플릿 (`templates/`) & Vanilla JS (`static/js/books.js`)
- **디자인 컨셉**: 다크 테마(Dark Mode), 세련된 글래스모피즘(Glassmorphism) 및 명예의 전당 골드 테마 디자인
- **반응형**: 태블릿(900px) · 모바일(640px) · 소형(340px) 3단계 브레이크포인트를 `mobile.css` 한 파일에서 관리
- **온디맨드 REST API**: 모듈화된 파셜 API 호출로 초고속 렌더링 성능 확보

## 🚀 시작하기

### 1. 환경 설정 (.env)

`.env.example`을 복사해 `.env`를 만들고 값을 채웁니다. 모든 설정은 `config.py` 한 곳에서만 읽습니다.

```bash
cp .env.example .env
```

```env
# 실행 환경: development | production
# production으로 두면 필수 시크릿이 비어 있을 때 서버가 기동되지 않고,
# API 문서(/docs)도 노출되지 않으며 HSTS 헤더가 부착됩니다.
APP_ENV=development

DATABASE_URL=mysql+pymysql://<DB_USER>:<DB_PASSWORD>@<DB_HOST>:<DB_PORT>/<DB_NAME>
GEMINI_API_KEY=YOUR_GEMINI_API_KEY_HERE

# ── 필수 시크릿 (운영에서 비어 있으면 서버가 기동되지 않습니다) ──
# 생성 예: python -c "import secrets; print(secrets.token_urlsafe(48))"
JWT_SECRET_KEY=<임의의 긴 무작위 문자열>
OWNER_ADMIN_EMAIL=<관리자 권한을 가질 계정의 이메일>

# ── 선택 설정 ──
ADMIN_SEED_EMAIL=admin@admin.com          # AI 사회자 봇 계정(로그인 차단됨)
ACCESS_TOKEN_EXPIRE_MINUTES=1440
# 다른 도메인에서 이 API를 호출할 때만 쉼표로 나열합니다. 와일드카드(*)는 금지됩니다.
# 개발 환경에서는 localhost의 모든 포트가 자동 허용되므로 비워두면 됩니다.
ALLOW_ORIGINS=https://yourdomain.com
# 비밀번호 재설정 메일에 담길 링크의 기준 주소 — 실제 접속 주소/포트와 반드시 일치시켜야 합니다.
APP_BASE_URL=http://127.0.0.1:8001
PASSWORD_RESET_TTL_MINUTES=30

# ── SMTP (비밀번호 재설정 메일 발송용) ──
# Gmail은 2단계 인증 활성화 후 '앱 비밀번호'를 발급해 SMTP_PASSWORD에 넣어야 합니다.
SMTP_SERVER=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=
SMTP_PASSWORD=
SMTP_FROM_EMAIL=
```

> [!IMPORTANT]
> 운영 배포 시에는 `APP_ENV=production`으로 설정하세요. 이 값이 `production`일 때만
> 필수 시크릿 검증(누락 시 기동 중단), `/docs` 비노출, HSTS 헤더가 활성화됩니다.

### 2. 의존성 설치

pip install -r requirements.txt

### 3. 애플리케이션 실행 방법 (두 가지 방식 지원)

#### Option A: FastAPI 서버를 실행하여 전체 서비스 이용 (추천)
실시간 AI 도서 생성, DB 저장, AI 사회자와의 채팅 기능 등을 모두 활성화하여 완전한 서비스를 이용하는 방법입니다.
```bash
uvicorn main:app --reload --port 8001
```
실행 후 브라우저에서 `http://localhost:8001`로 접속하여 가공독서회를 이용하실 수 있습니다.

> [!TIP]
> 다른 프로젝트가 이미 그 포트를 쓰고 있으면 `--port` 값만 바꿔서 띄우면 됩니다.
> 개발 환경(`APP_ENV=development`)에서는 localhost의 모든 포트가 CORS 허용 대상이므로 추가 설정이 필요 없습니다.
> 다만 비밀번호 재설정 메일 링크를 테스트하려면 `.env`의 `APP_BASE_URL`도 같은 포트로 맞춰주세요.

#### Option B: `index_standalone.html` 파일 더블클릭 (오프라인 미리보기)
서버를 가동하지 않고도 프론트엔드 UI 화면 디자인과 화면 전환 기능 등을 즉시 테스트하고 싶을 때 사용하는 방법입니다.
- 프로젝트 루트 폴더 안의 `index_standalone.html` 파일을 더블클릭하여 브라우저에서 즉시 열어볼 수 있습니다.

## 🔐 보안 설계 요약

인증·인가 관련 로직은 세 모듈에 모여 있습니다. 새 기능을 추가할 때 아래 규칙만 지키면 됩니다.

| 하고 싶은 일 | 사용할 것 |
|---|---|
| 새 환경변수·시크릿 추가 | `config.py`에 한 줄 추가 (필수값이면 `require_secret()`) |
| 로그인 필수 엔드포인트 | `Depends(auth.get_current_user_id)` 또는 `Depends(auth.get_current_user)` |
| 관리자 전용 엔드포인트 | `Depends(auth.require_admin)` — 엔드포인트 안에서 `is_admin`을 직접 검사하지 않습니다 |
| 호출 횟수 제한 | `security.RateLimiter` 인스턴스를 만들고 `check()`/`record()`/`hit()` 호출 |
| 비밀번호 변경 | `auth.set_password()` — 해시 교체와 기존 토큰 무효화가 함께 처리됩니다 |
| 사용자 문자열을 화면에 출력 | `textContent`, 또는 `innerHTML`이 꼭 필요하면 `escHtml()`을 반드시 통과 |
| DB 컬럼 추가 | `main.py`의 `_SCHEMA_PATCHES` 목록에 한 줄 추가 |
